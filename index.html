关于这个原型

一个面向「手持 SLAM 点云 + 建筑病害巡检」的 Web 端工作流演示

为什么做它

看完智眸三维的几篇推文（手持 SLAM 边走边扫、点云与 BIM 偏差比对），我按他们的业务链路做了一个能跑起来的原型： 扫描回放 → 点云浏览 → AI 预标注 → 人工复核 → 输出巡检报告。不是界面稿，是真的能点的系统。

技术栈

  • 渲染：three.js WebGL 点云，单批 22 万点、BufferGeometry 顶点色
  • 自定义轨道控制：旋转 / 缩放 / 平移 / 触摸双指，无第三方控制器依赖
  • 二进制点云解析：Float32 坐标 + Uint8 颜色/强度/扫描序号，按扫描序号重排后 setDrawRange 实现增量显示
  • 拾取：Raycaster + 点云阈值，点击即落点标注
  • 数据：程序化生成的建筑立面（24×13 m，4 cm 点距，±1.5 mm 噪声），含 3 条裂缝、2 处空鼓、1 处渗水、1 处幕墙错台、1 处钢筋外露
  • 导出：巡检报告 Markdown、病害清单 CSV（带 BOM，Excel 直接打开不乱码）

还能接什么

  • 导入自有 .ply / .xyz / .csv 点云（已实现，拖进「导入点云」即可）
  • 下一步：PotreeConverter 切片 + 八叉树 LOD，支撑上亿点在线浏览
  • 下一步：点云与 BIM 模型配准（ICP）、构件级偏差色谱
  • 下一步：多人在线协作标注、标注任务分派与质检
